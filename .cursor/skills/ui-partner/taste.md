# 审美：怎么看、怎么判断

这份文件讲判断方法。具体的版式、组件和数值在 `docs/新页面设计语言.md`，两者有出入时以设计语言为准，并把出入告诉 Gary。

## 好看在这里指什么

美育集的用户是画画的人。他们每天练的就是看整体、分主次、找关系，界面要经得起同样的眼光。

1. **作品是主角，界面是展墙。** 作品图、范画、书刊封面是这个产品的内容。它们周围用中性色，不铺带颜色的底，因为有色的衬底会改变人对画面颜色的判断。构图是画的一部分：大图不裁；列表里的图尽量按原比例显示，必须统一比例时也不能裁掉头、脚这类关键部位；图上不压标签。
2. **一屏只有一个重点。** 打开页面的第一眼落在哪，由你决定，而且只能有一处。其余内容按重要程度依次退后。四块同样大、同样重的东西并排，等于没有重点。
3. **正文先于摘要。** 用户来看的东西（清单、作品、书、表单）要在首屏出现。统计、小结、流程说明是辅助，收成一行或放到侧边，不能把正文挤到首屏以下。
4. **克制。** 颜色、容器、粗体都是有限的资源，用得越少，每一次使用越有分量。
5. **一件事只有一种做法。** 切换视图、筛选、搜索、主按钮、卡片、页头，在所有新页面里长得一样、位置一样。用户学会一页，就会用所有页。
6. **留白是结构。** 靠得近的东西是一组，隔得远的是两组。用间距分组，少用框线分组。同一层级的间距处处相等。空白要用来分组，不是内容没排满剩下的。
7. **用真实内容检验。** 最长的标题、最大的数字、只有一条数据、一条都没有，四种情况下版式都要成立。

几条容易数错的规矩：

- **品牌紫。** 只留给当前屏最重要的那个动作、对象本身的进行中状态（正在读、当前步骤、已收藏）和一处关键数字。控件的选中态（页签、筛选、菜单）不用紫。一屏里品牌紫的元素不超过三处，数的是首屏内容区里用品牌紫的东西：主按钮、紫色的图标、紫色的字和数字。浅紫底上写紫字的标签，每个算一处，所以十个「高分卷」标签就是十处；一张图表算一处；外壳（左导航、顶栏）不算；不写字的浅紫底不算，但不能成片出现。
- **状态色和科目色。** 绿、琥珀、红只表示状态，并且旁边有文字。科目色只用在科目标签上，不拿来写大数字、画进度条，也不和状态色紧挨着表达两种意思。
- **容器层数。** 外壳给的整块白色底板不算。从底板上的第一层容器算起，最多两层。
- **点击区域。** 指手指能点中的范围，不是看得见的大小。行、卡片、主按钮、页签这些主要目标，点击区域的宽和高都不小于 44，看得见的部分可以小一些。这一条图上看不出来，要读代码确认。
- **要读的字。** 用户需要读的信息不用占位灰（`textPlaceholder`），也不小于 12 号。说明、时间、数量这类辅助信息用三级文字色。

## 评的顺序

和评一张画一样，从大到小。四层都要评、都要记下来；改的时候先解决前面的层，因为大关系不对，细节调得再好也没用。

1. **整体。** 把图缩小到看不清字。页面分成几块？各占多大？有没有一块明显是主体？颜色最重的地方是不是该重的地方？
2. **主次。** 第一眼落在哪？那是不是用户来这一页最想看或最想做的？第二眼、第三眼的顺序对不对？有没有两处在抢？同一件事、同一个数有没有说了两遍？
3. **节奏。** 间距是不是只有少数几种？左边缘对齐到几条线？同类的东西是不是一样大？疏密有没有变化，还是从头到尾一样挤？
4. **细节。** 文字有没有被截断或被别的东西压住？数字和单位是否对齐？图标是不是同一套、同一粗细？圆角、描边是否统一？同一个东西的叫法前后是否一致？

写评语时说具体的位置、具体的现象和它对用户的影响。「首屏同一件事出现两次，头图里的卡片和清单第一行各有一个主按钮，用户不知道点哪个」是评语；「不够高级」不是。也要写清楚哪些地方是好的、应该保留。

## 这个项目里出现过的毛病

下面这些都来自改版前的真实页面（详见 `docs/走查/新页面现状问题清单.md`）。它们很容易再犯，改完自己对一遍。

| 毛病 | 当时的样子 | 改法 |
| --- | --- | --- |
| 同一件事多种做法 | 切换视图有四种控件；筛选选中有深色实底和紫色描边两种；主按钮有紫色和深色两种；同一种状态标签在学生和老师那里颜色、形状不同 | 只用设计语言里的那一种 |
| 颜色太多 | 今日的数字卡和图标底座用了紫、粉、青、琥珀、蓝五种；学情用三种科目色写大数字；绿色同时表示「已点评」「色彩」和「进步」 | 同一层级的图标用同一种中性样式；颜色只留给状态和选中 |
| 大面积品牌色 | 今日的整块紫色渐变头图；书刊网格里浅紫底的卡片；班级学情两张图表的大片紫色 | 品牌紫只做点睛；大面积的颜色只出现在设计语言规定的位置 |
| 层层嵌套 | 白色底板里放描边卡片，卡片里放灰底块，灰底块里再放图标底座 | 容器最多两层，其余用间距和细线分组 |
| 同一件事说几遍 | 今日的「下一步」在头图和清单第一行各有一个主按钮；学生的「11 件」在首屏出现六处；成绩报告把总览的成绩卡原样再放一遍；小课件卡片里同一张封面放了两次 | 一件事在一屏里只有一个入口，一个数只出现一次 |
| 一排一样的按钮 | 工具箱十一张卡片各带一个深色「去使用」；复核池每行一个「复核」；清单每行一个按钮 | 整行或整张卡片可点；按钮留给与众不同的那个动作 |
| 视图切换用了主按钮 | 学情的「成长曲线」是紫色主按钮，其实只是换个视图 | 主按钮只给会产生结果的动作；切换视图用切换控件 |
| 摘要挤走正文 | 今日的第一条待办在首屏七成以下；作品档案首屏三分之二是统计和小结；点评工作台里流程卡把表单挤到首屏以外 | 用户来看、来做的内容先出现；摘要收成一行或放到侧边 |
| 图被裁、被压 | 集市和作品墙把竖幅作品裁掉头和脚；书刊封面上叠着阶段、收藏、进度三个标签，盖住封面自己的标题 | 按原比例显示；标签放到图的外面 |
| 文字截断 | 书名「联考素描静物高分解…」；1024×768 下今日的说明文字截掉的正是时间和数量 | 给够两行，或让封面自己说话，下面不重复 |
| 要紧的字最淡 | 工具卡的说明是 11 号占位灰；阅读进度、库存、难度这些要看的信息是最小最淡的字 | 要读的字不用占位灰，不小于 12 号 |
| 看不出在哪一页 | 多数新页面没有可见标题；导航叫「优秀课件」，页内叫「小课件」又叫「专题」；集市、作品、工具箱、教学报告打开后左导航没有高亮项 | 页头按设计语言处理；名称对不上时请 Gary 定 |
| 状态颜色帮倒忙 | 进度条越接近完成红色越长；「低于平均 1.7 分」标红；十张卡片各带一个一样的「待点评」 | 颜色的含义和程度要对得上；人人都有的标记不带信息，去掉 |
| 画的底色带蓝 | 范画详情、对比页、作品卡的底是 `surfaceSubtle`（#F5F6FA），白纸素描衬在上面发蓝 | 画背后用 `AppColors.canvas` / `canvasDark` |
| 操作压在画上 | 每张范画右上角一个白底星标；全屏按钮、缩放提示压在画的角上 | 小操作放在名称右边或画布下面一行 |
| 一句话说三遍 | 筛到「联考高分卷」时，筛选项、图上标签、标题都写「高分卷」 | 已经由筛选说明的，格子里不再说 |

## 拿不准的时候

- **删掉试试。** 去掉一个元素后页面没有变差，它就不该在。先删，再考虑加。
- **缩小看。** 用 `SCALE=0.25` 渲染一张小图，还能一眼看出重点和分区，大关系就是对的。
- **换成最长的内容。** 想一想最长的标题、最大的数字放进去会怎样；演示数据里有长内容时就用它渲染。
- **和邻居放一起。** 和已经统一的新页面、保留的首页并排看，像不像同一个应用里的页面。
- **两个都做出来。** 两个方案在脑子里分不出高下时，各渲染一张再比，不要靠想。

## 交付前自己过一遍

对着改完后的渲染图逐条看，两种尺寸都要看。标「代码」的几条图上看不出来，要读代码确认。

整体与主次
- 缩小后能看出一个主体，分区不超过四块。
- 第一眼落在用户最想看或最想做的那一处；它在首屏以内。
- 一屏只有一个主按钮；品牌紫不超过三处。
- 同一件事、同一个数在一屏里只出现一次。

节奏
- 页面边距、分区间距、卡片间距各只有一种值，取自设计语言。
- 左边缘对齐到少数几条线；同类元素等宽等高。
- 容器不超过两层。

细节
- 没有被截断、被压住的文字；最长的内容也放得下。
- 数字用数字字体，单位紧跟其后，同一列对齐。（代码）
- 作品图周围是中性色；图片没有被拉伸，关键部位没有被裁掉，图上没有压标签。
- 状态除了颜色还有文字。
- 要读的字不用占位灰，不小于 12 号；字号只有规定的那几档。（代码）
- 只有图标的按钮有读屏名称；主要目标的点击区域不小于 44。（代码）
- 页面有可见的名称，和入口的叫法一致；左导航的高亮是对的。

状态与尺寸
- 加载、空、出错三种状态存在，并且和正常状态占同样的位置。渲染不出来的状态读代码确认，并在交付时说明。
- 1024×768 下没有版式警告、没有挤压变形，主按钮仍在首屏以内。
- 不同身份看到的版本都渲染过。
