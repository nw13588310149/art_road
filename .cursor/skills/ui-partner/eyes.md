# 眼睛：怎么看到页面

改界面之前和之后都要看渲染出来的图。有两条路：日常用快速预览，交付前用真实浏览器补一次。

## 一、快速预览

`tool/qa/page_preview_test.dart` 用应用自己的路由、外壳、主题、演示后端和本地媒体服务把页面渲染成 PNG，带左导航和顶栏。不需要构建，每张图 2 到 4 秒。

```powershell
flutter test --no-pub tool/qa/page_preview_test.dart `
  "--dart-define=SHOTS=ebooks,ebook-detail" "--dart-define=LABEL=before"
```

带逗号的参数在 PowerShell 里要整体加引号，像上面那样。bash 里把行尾的反引号换成反斜杠。同一时间只跑一个 `flutter` 命令，并行运行会抢同一个构建目录。

参数都可以省略：

- `SHOTS`：镜头 id，逗号分隔，按前缀匹配。`ebook` 会选中 `ebooks`、`ebooks-shelf`、`ebook-detail`。省略时渲染清单里的全部镜头。
- `ROLES`：身份，逗号分隔，可用 `student` `teacher` `groupLeader` `headTeacher` `dormManager` `admin` `principal`。省略时用镜头自己标注的身份。
- `SIZES`：整屏尺寸，逗号分隔，默认 `1180x820,1024x768`。
- `LABEL`：输出子目录，默认 `current`。
- `SCALE`：像素比，默认 `2`。
- `CROP`：只导出一个区域，写法是「左,上,宽,高」，单位是逻辑像素，以整屏左上角为原点。
- `ROUTE`：临时看一个不在清单里的路由，问号后面是字符串路由参数，例如 `/toolbox?tool=grid`。默认用学生身份，要换身份加 `ROLES`。
- `TAPS`：配合 `ROUTE`，进入后依次点击的文字，多个用加号连接，例如 `我的书架+在读`。

图片在 `build/qa/preview/<LABEL>/<宽>x<高>/<身份>-<镜头>.png`，运行结束时会列出每一张的路径。用读文件工具直接打开 PNG 来看。`build/` 不入库。

### 常用做法

- **改版前后各存一份。** 动手前用 `LABEL=before` 渲染要改的镜头，改完用 `LABEL=after` 渲染同样的镜头，两张图挨着打开比较。
- **看大关系。** 读文件工具会把整屏图缩到一千像素宽左右，适合看版式，不够小也不够大。要只看大关系，用 `"--dart-define=SCALE=0.25"` 渲染一张看不清字的小图。
- **看细节。** 小字、截断、对齐、一两个像素的重叠，在整屏图上看不清。用 `CROP` 放大一块，例如 `"--dart-define=CROP=640,190,330,130" "--dart-define=SCALE=3"`。坐标按 1180×820 或 1024×768 的整屏来估，左导航占左边 178，顶栏占上面 72。
- **看首屏以下。** 把高度加大到页面不再被截断为止，例如 `"--dart-define=SIZES=1180x2400"`。左导航会跟着拉长，内容区一次显示更多。不同身份内容不同时，每个身份各渲染一张。判断首屏时仍然用标准尺寸。
- **看不同身份。** 一个页面对不同身份内容不同时（今日、学情、作品、集市的审核入口），每个身份都要渲染，例如 `"--dart-define=ROLES=student,teacher,principal"`。
- **固定一个新状态。** 页面有清单里没有的状态（页签、抽屉、详情、表单）时，在文件顶部的 `_shots` 里加一行。`steps` 里普通字符串表示「点击包含这段文字的第一个控件」，`tip:返回` 点击图标按钮的提示文字，`scroll:400` 把内容区向上滚 400，`wait:800` 多等 800 毫秒。路由参数不是字符串时（教学报告用的是 `TeachingRequest`）只能写在 `_shots` 里，`ROUTE` 传不了。
- **留意版式警告。** 渲染时出现溢出等异常不会中断，会记在同名的 `.warnings.txt` 里，并在结尾汇总成 `warn`。没有这个文件就是没有异常。有警告的图要打开看，溢出通常就是问题所在。

### 它和真实应用的差别

判断时要心里有数：

- **每次都从初始演示数据开始**，相当于刚点过「重置演示数据」。所以「我的订单」「集市审核」这类页面渲染出来是空状态。要看有数据的样子，在 `steps` 里先把数据做出来，或者走第二条路在浏览器里操作之后再截图。
- **时间是运行时的真实时间。** 今日清单、课表这类内容每次渲染可能不同，改版前后的两份要挨着渲染。演示数据在 08:30 之前和 21:30 之后会把「现在」算成前一个晚上，和页面自己显示的真实时间对不上，尽量在这之间渲染。
- **随机内容每次不同**，例如明度排序训练的色块顺序。
- **`pubspec.yaml` 里没有声明的字体显示成方块。** 目前只有保留的首页上资讯卡的 NEW 角标。
- **全屏页面不带外壳**，例如范画对比、原卷查看，这是页面本身如此。
- 随页工具栏和小画不在图里。
- 视频、PDF、相机这类依赖原生插件的内容不显示。

渲染不出加载中、出错、空数据这些状态时，读代码确认它们存在、占的位置和正常状态一致，并在交付时说明没有看到实图。

### 遇到问题

- 「找不到要点击的…」：文字不在当前屏幕上，或者被别的控件挡住。先不带这一步渲染，看图确认文字，再调整步骤。
- 警告里写「等了 8 秒页面仍在加载」：图里还有转圈或骨架屏。先看是不是页面真的卡在加载，再考虑给步骤加 `wait:`。
- `MissingPluginException`：页面用到了测试环境里没有的原生插件。在 `_mockPlugins` 里给那个通道加一个替身。

## 二、真实浏览器截图

`tool/qa/web_shot.mjs` 让本机的 Chrome 在无界面模式下打开网页构建并截图，渲染结果和用户在浏览器里看到的一致，小画和随页工具栏都在。每张约 10 秒，改了代码要重新构建。它只用 Node 自带的能力，不需要 Playwright。

```powershell
powershell -ExecutionPolicy Bypass -File tool\build_web.ps1          # 约 1 分钟
python -m http.server 8787 --bind 127.0.0.1 --directory build/web    # 放到后台运行

node tool/qa/web_shot.mjs --role=student --route=/ebooks --out=build/qa/web/student-ebooks-1180.png
node tool/qa/web_shot.mjs --role=teacher --route=/artworks "--tap=开始点评" --size=1024x768 `
  --out=build/qa/web/teacher-artwork-review-1024.png
```

`--tap` 按无障碍名称匹配，多个用竖线分隔并整体加引号。其余参数见脚本开头的说明。用完把静态服务停掉。

什么时候用它：

- 交付一个页面前，对入口屏在两种尺寸下各截一张，确认和快速预览一致。
- 需要确认小画或随页工具栏没有挡住关键内容，例如右下角的主按钮。
- 页面里有快速预览显示不了的内容。

## 三、Cursor 内置浏览器

内置浏览器适合打开网页构建，按无障碍树点一遍流程，确认按钮确实能用。它的截图只能截到面板可见的那一块，截不出整屏，所以不用它来判断版式。在自动化浏览器里点击 Flutter 页面之前，先点一下 `flt-semantics-placeholder` 打开无障碍树。

## 四、看图的方法

- 先看缩小的整图，再看细节。整图回答「重点在哪、分成几块」，细节回答「对没对齐、字清不清楚」。
- 两种尺寸都看。1024×768 的内容区只有 814×680，最容易暴露挤压和截断。
- 把要改的页面和它的邻居放在一起看：已经统一的新页面（见 `docs/走查/新页面统一进度.md`），以及保留的首页（镜头 `ref-home`）。用户是在它们之间来回切换的。设计语言的样板是 `docs/走查/新页面示例/` 里的图，以及组件库演示页最上面的「新页面组件」一节（镜头 `kit`）。
- 有些事图上看不出来，要读代码确认：点击区域的大小、只有图标的按钮有没有读屏名称、用的是不是数字字体、字号是不是规定的那几档。
