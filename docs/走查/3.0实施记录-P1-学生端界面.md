## 演示后端：优秀作品对全校公开（第 5 项）

- `lib/core/demo/data/demo_artwork_data.dart`
  - `DemoArtworkAccess` 增加 `featured`（作品已被推优）和 `publicReader`（只因推优才读得到：不是本人，对这份作品也没有教职权限）。
  - `canRead` 改为「本人、有教职权限，或作品已被推优」。进入复核的原因（`seesLeadReasons`）和点评质量星级（`seesQuality`）仍只给责任老师、本组组长、校长、管理员，所以公开读者看到的就是规格 2.2 表里「学生」一列。
  - 推优只多给一份只读权限，`canReview`、`canSupplement`、`canComment`、`canFeature` 的算法没动；撤销推优后 `featured` 为假，权限回到原样。
- `lib/core/demo/fixtures/marking_artwork_fixtures.dart`
  - `GET /app/artworks/{id}`：本人的作品，或被推优的作品（任何身份）。没被推优的作品，学生读别人的仍返回 404，教职身份仍返回 403（走教职详情接口）。
  - 返回里补了三处：`access.owner`（是不是本人，界面据此决定有没有「改画重交」）；`work.className`（班级）；公开读者的 `versions` 只留被推优的版本，同一条改画链上没被推优的版本不给看。
  - `GET /app/artworks/excellent`：每条补 `className`（规格 2.6 要求带学生姓名和班级，原来只有校区 `organizationName`）。
  - `_readableWork` 去掉不再使用的 `studentPerson` 参数。
- 单测 `test/artwork_featured_access_test.dart`（10 项）：公开读者的可见范围与不能操作；推优前后各身份的其余权限不变；各身份读同一份被推优作品时的差别；别人的作品不能改画重交、不能点评、不能复核、不能补充点评、不能读批注接口；撤销推优后学生 404、教职 403；本人拿到 `owner`；公开读者只看到被推优的版本；优秀作品墙列表带姓名和班级。
