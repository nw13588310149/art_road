## 0. 已确认的决定

| 问题 | 决定 |
| --- | --- |
| 组长是谁 | 教学组长（素描组、色彩组、速写组），即「任课老师 + 组长权限」，不是单独的登录身份 |
| 点评链怎么扣 | 老师点评后学生立即可见；组长只复核触发条件的作品，调分后以组长为准；校长不设必经环节，随时可看可评，可推优 |
| 作业和作品 | 智慧校园的作业并入作品档案：作业就是带要求的作品任务，提交物都是作品，走同一条点评链 |
| 做到什么程度 | 在演示版里做全，演示后端按真实接口格式造数；新接口写进后端缺口清单 |
| 校长的数据范围 | 总校长看全部校区，可切换到单个校区 |
| 老师履职指标 | 点评及时率、点评质量、上课签到准时率、作业布置与批改、所带学生成绩变化；老师看自己，组长看本组，校长看全部，学生看不到 |
| 做法 | 不推倒重写，在现有架构上分期改；每期本地提交，不经同意不推送 |

**审阅时请重点确认一处规则变化**：2.0 的日常作品由多位老师盲评、取平均分。新链路改为每份作品有一位责任老师（按科目的任课老师），最终分取责任老师的分数或组长调整后的分数；其他老师可以补充点评但不计分。原因：日常练习要有人负责、反馈要快，取平均会把责任摊薄，也要等所有老师评完才出分。模考仍由阅卷系统多评，不受影响。

## 1. 目标

1. **UI**：还原音乐之路原版是第一原则。新页面不引入新的视觉语言，只用原版已有的版式和 `lib/core/ui` 组件。
2. **学生端**：围绕「练什么 → 交作品 → 看点评 → 改画 → 看到进步」组织。学生打开 App 就知道今天该做什么、上次的问题改好没有。
3. **校长和教师端**：校长打开首页就能看到全校今天的情况：老师在不在岗、点评有没有积压、各班学得怎么样、哪些学生需要关注。每个数字都能点进去，看到具体的人和作品。
4. **点评链**：学生提交 → 任课老师点评 → 组长复核 → 校长抽看。每一环的结果都回到学生端，同时沉淀为学生能力画像、老师履职数据和全校看板。

**验收场景**（iPad 预览包上用演示身份走一遍）：

1. 学生交一幅作品；
2. 任课老师点评并请组长复核；
3. 组长调分并评价这次点评；
4. 校长点评并推优；
5. 学生看到完整时间线，改画重交；
6. 校长驾驶舱里对应的数字和动态随之变化。

## 2. 设计原则

1. **原版优先**：外壳、左侧导航、首页骨架、智慧校园看板都沿用音乐之路。新页面从原版里找最接近的版式改内容，每页的参照写在第 6～9 节。
2. **一份数据**：作品、点评、任务只存一份。学生、老师、组长、校长看到的是同一条记录的不同视角。
3. **反馈要快**：复核和校长点评都是追加，不阻塞学生看到老师点评。
4. **数字能落到人**：所有统计都能下钻到具体的老师、班级、学生或作品。
5. **一页只回答一个问题**：首屏指标不超过 8 个；红色只用于异常。
6. **合规**：界面文案不承诺提分，不用绝对化用语，过 `yikao-marketing/brand/compliance/banned-words.json`。老师履职数据只给本人、组长和校长看，界面叫「履职概览」，不做公开排行榜。
7. **演示版先行**：演示后端按真实接口格式造数，演示数字照常标注「演示数据」。

## 4. 主线：作品点评链

### 4.1 流程

```
（可选）老师布置作业
   ↓
学生提交作品（关联作业，或自主练习）
   ↓
责任老师点评：总分 + 四项分项 + 标签 + 评语 + 批注 + 语音（可选）──→ 学生立即可见
   ↓ 满足任一触发条件
组长复核：维持 / 调分（必填理由）/ 补充评语；并给这次点评打质量星级 ──→ 学生看到复核记录
   ↓ 任何时候
校长：查看 / 点评（追加一条）/ 推优到优秀作品墙 ──→ 学生和老师收到消息
   ↓
学生看点评时间线 → 改画重交（新版本挂在原作品下）→ 回到责任老师点评
```

### 4.2 状态

| 状态 | 含义 | 学生端显示 |
| --- | --- | --- |
| 待点评 | 已提交，责任老师未点评 | 待点评 |
| 已点评 | 责任老师已点评，未进入复核 | 已点评 |
| 复核中 | 已进入组长复核池，组长未处理 | 已点评，附小标「复核中」 |
| 已复核 | 组长已处理 | 已点评，时间线里有复核记录 |

另有三个独立标记：「校长点评」「优秀作品」「有改画版本」。「复核中」「已复核」是新增状态词，需要同步补进 `docs/设计规范.md` 第 7 节。

### 4.3 规则

**分配**
- 每份作品按科目分给该生的任课老师，这位老师就是责任老师。
- 关联作业的作品，分给布置作业的老师。

**时限**
- 责任老师在提交后 24 小时内完成首评；超时在教师工作台标红，并计入校长驾驶舱的「超时待点评」。
- 组长在作品进入复核池后 48 小时内处理。
- 两个时限由教务设置，上面是默认值。

**进入复核池的条件**（满足任一即可，复核池里标出原因）
1. 老师勾选了「请组长复核」。
2. 分数异常：与该生最近 5 次同科得分的均值相差不少于满分的 15%。
3. 点评过简：评语少于 20 字，并且没有批注。
4. 抽查：按比例随机抽取，默认 20%，教务可在 10%～50% 之间调整。

**复核结果**
- 维持：最终分不变。
- 调分：必须填理由，至少 10 字。最终分改为组长的分数，学生的时间线里同时保留老师原分和组长调整记录。
- 补充评语：在时间线里追加一条，最终分不变。
- 点评质量星级：组长每次复核都要给 1～5 星，可以附一句意见。老师本人和校长可见，学生不可见。

**校长**
- 校长点评在时间线里追加一条，标注「校长点评」，不改分。
- 推优：作品进入优秀作品墙，学生、责任老师和班主任收到消息。可以撤销。

**改画重交**
- 学生在作品详情里点「改画重交」。新版本挂在原作品下（第 2 版、第 3 版），仍由同一位责任老师点评。
- 老师点评新版本时，左右对照上一版和上次的点评，并把上次的问题标签逐个标为「已改善」或「仍需加强」。这个标记是「问题解决率」的来源。

**消息**
- 点评、复核、校长点评、推优、超时提醒都发消息，`targetType` 为 2（作品）。通知跳转沿用 `shell_notice_routes.dart`。

### 4.4 分项评价

每个科目四项，每项 5 级：待加强 / 一般 / 合格 / 良好 / 优秀。

| 科目 | 四项 |
| --- | --- |
| 素描 | 构图、造型、明暗、刻画 |
| 色彩 | 构图、造型、色彩关系、刻画 |
| 速写 | 构图、比例动态、线条、刻画 |

- 点评标签增加「所属分项」属性（可以不填），标签统计也能归到分项上。
- 分项是学生能力画像的来源。取最近 10 份已点评作品，逐科计算。

| 全校学情 | 各班模考均分走势和作品分项对比，点班级进入学生名单 | 学情中心「班级学情」 |
| 需要关注的学生 | 按规则分组的名单，每人写原因和负责老师，点开是学生档案 | 智慧校园「学生管理」 |
| 作品点评链 | 按日看提交、已点评、复核中、已复核的数量和超时，下方是作品列表；校长可以点开任意作品点评或推优 | 作品点评队列 |

## 10. 指标口径

**老师履职**（老师看自己，组长看本组，校长看全部）

| 指标 | 口径 | 周期 |
| --- | --- | --- |
| 点评及时率 | 提交后 24 小时内完成首评的作品数 ÷ 期内应评作品数 | 近 7 天 |
| 点评质量 | 组长质量星级均值（1～5）；辅助看评语平均字数、批注率、分项填写率 | 近 30 天 |
| 上课签到准时率 | 课表上的课节中，老师在开课 10 分钟内发起课堂签到的比例 | 近 7 天 |
| 作业布置与批改 | 布置的作业数；作业提交的批改完成率 | 近 30 天 |
| 所带学生成绩变化 | 所带学生最近一次与上一次模考的同科均分差 | 每次模考 |

组长和校长另看「调分率」：被调分的作品数 ÷ 被复核的作品数，近 30 天。

**学生学情**

| 指标 | 口径 |
| --- | --- |
| 作品提交率 | 当天（或当周）有提交的学生数 ÷ 班级人数 |
| 问题解决率 | 被标为「已改善」的问题标签数 ÷ 出现过的问题标签数 |
| 连续练习天数 | 截至今天，连续有作品提交的在校日数 |
| 分项水平 | 最近 10 份已点评作品的分项等级均值，按科目计算 |

**需要关注的学生**（满足任一即列入，写明原因）
1. 最近两次模考总排名下降 5 名或以上；
2. 连续 3 个在校日没有交作品；
3. 同一问题标签连续 3 次出现且未改善；
4. 近 7 天缺勤 2 次或以上。

## 13. 演示数据

- **身份**：新增「校长」（看全部校区）和「组长」（由一位素描老师兼任素描组长）。演示任课老师仍是普通老师，保证「老师 → 组长 → 校长」能由三个不同的人演示。

- **写入**：新产生的提交、点评、复核写入 `DemoStore`，「重置演示数据」一并清除。

## 16. 风险与待确认

1. **责任老师规则**：见第 0 节末尾，审阅时请确认。
2. **履职数据敏感**：只给本人、组长和校长看，不做公开排行榜；老师能看到自己的数据和组长评价。
3. **真实后端**：作业和作品分属两套接口，并入后放哪一侧需要后端决定。老师在两套系统里的身份也要一一对应，见后端缺口清单「需要决策」第 3 条。
4. **院校数据**：院校分数线需要权威数据源，本期只做「目标分」。
5. **合规**：「今日任务」「我的短板」等文案只描述练习和变化，不写提分幅度或结果承诺。
