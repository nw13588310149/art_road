# 美育集架构方案

本文定架构和需求，是后续代码改动的依据。实施中出现的新取舍记在第 9 节。

## 1. 定位与已确认的决定

App 分两个板块，靠同一条数据链连接：**智慧教学**产生记录，**智慧教务**读这些记录。

- 智慧教学：以学生的作业为基础，按「学生 → 科目老师 → 科目组长 → 指定校长」形成闭环。
- 智慧教务：校长通过 App 管理学校日常，看得到老师的教学行为，看得到每一个学生有没有被关注。

已确认：

| 编号 | 决定 |
|---|---|
| D1 | 一所学校可以有多位校长，闭环的末环由指定的那位校长查看 |
| D2 | 组长逐份查看，组长有自己的点评和操作 |
| D3 | 「老师布置的作业」和「学生自己上传的作品」合并成一条流程 |
| D4 | 学生可自己付费，画室走批量采购；同时服务个人用户和画室学生 |
| D5 | 老师的行为数据：校长、教务可看全校，组长看本组，老师看自己 |
| D6 | 老师点评完成后学生立刻可见，组长点评随后追加 |
| D7 | 校长按批次查阅，可点进任意一份写批示 |
| D8 | 分管校长按班级或校区指定 |
| D9 | 不分期，一次做完 |
| D10 | 可以改动从音乐之路继承来的模块，按两大板块重排左侧导航和智慧校园，项目规则文件同步更新 |
| D11 | 分管校长：每个校区指定一位，个别班级可以另行指定 |

## 2. 组织与角色

组织：学校 → 校区 → 班级；另有按科目划分的科目组（素描组、色彩组、速写组）。

| 角色 | 现状 | 新架构里的职责 |
|---|---|---|
| 学生（画室） | 有 | 交作业、看点评、改画 |
| 个人用户 | 无（现在不绑定画室进不去） | 自主练习，使用范画、工具、课程 |
| 科目老师 | 有 | 布置作业、点评 |
| 科目组长 | 无 | 逐份复核本组点评，看本组数据 |
| 班主任 | 有 | 跟进本班被落下的学生 |
| 教务 | 有（即现在的管理员） | 学籍、排课、审批等日常事务 |
| 校长 | 有名无实（复用管理员界面） | 查阅分管班级的作业，使用驾驶舱，发起督办 |
| 宿管 | 有 | 不变 |
| 家长 | 无 | 查看孩子的点评与成绩（只读）、请假确认、家校沟通 |

可以复用的基础：

- 后端的教师角色本来就是一个集合（校长、教务、宿管、班主任、任课老师），一人可兼多职。需要新增「科目组长」，并给校长加「分管范围」（班级或校区）。
- 教师详情里已有「教研角色」一栏，演示数据按科目生成教研组名称。缺的是把组长做成可操作的身份。
- 班主任「家校沟通」的数据里已有家长的 ID、姓名和关系。缺的是家长这一端的登录和页面。

## 3. 智慧教学：作业闭环

### 3.1 统一用词

| 词 | 含义 |
|---|---|
| 作业 | 老师或组长的一次布置（班级、科目、要求、截止时间） |
| 作品 | 学生交上来的一份画（一张或多张照片）。属于某次作业，或是自主练习 |
| 自主练习 | 没有对应作业、学生自己上传的作品 |
| 点评 | 老师对一份作品的评分、评语、问题标签、图上批注、语音 |
| 复核 | 组长逐份查看老师的点评 |
| 查阅 | 校长环节 |
| 批次 | 一次作业在一个班的全部作品；自主练习按班、按周汇成一个批次 |

### 3.2 一份作品的流转

| 状态 | 处理人 | 可做的动作 | 之后 |
|---|---|---|---|
| 待提交 | 学生 | 拍照上传 | 待点评 |
| 待点评 | 科目老师 | 评分、评语、标签、批注、语音；可要求改画 | 待复核，或待改画 |
| 待复核 | 科目组长 | 通过；写组长点评；改定分数（留痕）；退回老师重评；要求改画；标为范例；标记该生需关注 | 已完成，或退回待点评，或待改画 |
| 待改画 | 学生 | 重新上传，旧版本保留，可前后对比 | 待点评 |
| 已完成 | 无 | 学生查看，系统记录是否已读 | 进入成长档案 |

- 「待提交」只有布置的作业才有，未交名单由此而来。
- 自主练习从「待点评」开始，按科目进入该生任课老师的队列。个人用户没有老师，作品只进自己的成长档案。
- 老师点评完成后学生立刻能看到，组长点评随后追加（D6）。组长改定分数或退回重评时，学生看到的内容随之更新，并保留修改记录。

### 3.3 校长环节

- 指定方式：每个校区指定一位分管校长，个别班级可以另行指定（D8、D11）。班级上的指定优先于校区。
- 一位校长看到的是分管班级的全部科目批次。
- 查阅单位：按批次，不按单份（D7）。
- 校长在一个批次上能看到：应交、已交、已点评、已复核、超时数量；未交名单；分数分布；组长标出的范例和需关注学生。
- 校长可以点进任意一份作品写批示，可以对批次确认已阅，可以发起督办。
- 一个批次闭环完成的标准：全部作品已完成，且校长已阅。

### 3.4 时限与上报

点评时限和复核时限由学校设置。超时先提醒本人；仍未处理则上报上一级（老师超时报组长，组长超时报分管校长），并计入教务数据。

### 3.5 挂在教学下的辅助功能

范画库、画室工具箱、校园课件、视频、书刊、小美同学、学情（考试成绩）。点评里的问题标签继续用来推荐范画和工具，这一点现在已经有了。

## 4. 智慧教务：校长驾驶舱

驾驶舱三个页签，对应校长每天要回答的三个问题。

### 4.1 今日：学校今天怎么样

出勤、请假、查寝、课表执行、待审批、校长信箱、通知。现有智慧校园已基本具备，主要是汇总到一页。

### 4.2 教师：老师有没有尽责

| 指标 | 算法 |
|---|---|
| 点评及时率 | 时限内完成的点评数 ÷ 应点评数 |
| 积压 | 当前已超时仍未点评的份数 |
| 点评用时 | 从学生提交到点评完成的中位时长 |
| 被退回率 | 被组长退回重评的份数 ÷ 已点评份数 |
| 学生覆盖 | 名下学生中，近 N 天至少得到一次点评的比例 |
| 学生已读率 | 点评被学生打开的比例 |
| 点评内容 | 评语字数、标签数、有无批注或语音。只作参考，不单独排名 |
| 布置次数 | 周期内布置的作业数 |
| 到岗 | 上课签到签退、请假（现有数据） |

组长另有：复核及时率、复核量、退回率、组长点评数。

### 4.3 学生：有没有人被落下

这部分和现状的差别很大。现在只有班主任手动添加的「重点关注」，没有反过来找「没人关注」的学生。

- **被落下名单**。命中任一条就进名单，阈值由学校设置：
  - 近 N 天没有提交任何作品
  - 提交后超过时限没人点评
  - 近 N 天没有得到任何点评
  - 连续多次未交作业
  - 考试名次连续下滑（学情里已有名次变化数据）
  - 出勤、请假、查寝异常（现有数据）
- **关注分布**。按成绩档（A 到 E）统计人均被点评次数和评语量，直接看出老师的精力是不是集中在前几名。
- **校长轮看**。记录每位校长看过哪些学生的作品，每天从最久没被看过的学生里给出「今日建议查看」，一个周期内看遍分管范围的所有学生。
- **学生档案**。一个学生一页：作品时间线、点评、考试成绩、出勤、请假、查寝、班主任记录。

### 4.4 督办

校长或教务对一个学生、一位老师或一个批次发起督办：指派给班主任、老师或组长，设截止时间，对方填写跟进记录后关闭。超期提醒。这是教务侧的闭环。

## 5. 导航与各角色入口

左侧导航：首页、智慧教学、智慧教务、消息（群聊、校圈、通知）、我的（云盘、笔记、收藏、个人中心）。

| 角色 | 智慧教学 | 智慧教务 |
|---|---|---|
| 学生（画室） | 我的作业、成长档案、学情、范画库、课件与视频、工具箱、小美同学 | 课表、签到、请假、查寝、通知 |
| 个人用户 | 自主练习、成长档案、范画库、课件与视频、工具箱、小美同学 | 无此板块 |
| 科目老师 | 布置作业、作业点评、班级学情、我的教学数据 | 授课课表、签课、请假 |
| 科目组长 | 老师的全部，加组内复核、本组数据 | 同老师 |
| 班主任 | 本班作业概览、本班学情 | 班级工作台、请假审批、查寝、家校沟通、本班被落下名单、督办跟进 |
| 教务 | 全校作业概览 | 学生、教师、班级管理，排课，签课，审批，通知，人脸库 |
| 校长 | 教学查阅、全校学情 | 驾驶舱、督办、校长信箱 |
| 宿管 | 无此板块 | 查寝、到岗、请假 |
| 家长 | 孩子的作业点评与成绩（只读） | 请假确认、家校沟通、通知 |

学生端和家长端的「智慧教务」显示为「校园」，内容不变。

## 6. 个人用户与画室学生

| | 个人用户 | 画室学生 | 教职工 |
|---|---|---|---|
| 进入方式 | 自己注册，不绑定画室 | 输入画室编码绑定（现有） | 画室开通 |
| 付费 | 自己购买会员 | 画室批量采购后发放（现有兑换码可承接） | 随画室，不单独付费 |
| 能用什么 | 自主练习、成长档案、范画、课程、工具、小美同学 | 上述全部，加作业闭环和校园事务 | 按角色 |

需要改的现有行为：

- 绑定画室的弹窗现在关不掉，要改成可以选择「先以个人身份使用」。
- 会员现在是全有或全无（过期后除个人中心外全部拦截），要改成分层：哪些功能不需要会员，哪些需要。
- 个人购买流程现在没有，只有兑换码。

## 7. 现有模块的去向

| 现有 | 去向 |
|---|---|

| 学情（阅卷成绩） | 智慧教学下，同时给驾驶舱和学生档案供数 |

| 班主任「重点关注」 | 并入学生关注，和被落下名单放在一起 |
| 班主任「家校沟通」 | 保留，补上家长这一端 |
| 校长信箱、通知管理 | 智慧教务 |
| 范画库、工具箱、课件、视频、书刊、小美同学 | 智慧教学的辅助 |
| 群聊、校圈 | 消息 |
| 云盘、笔记、收藏、个人中心 | 我的 |

## 8. 实施顺序

不分期，一次做完（D9）。代码之间有先后依赖，按下面的顺序做，每一步做完演示版都要能正常运行并通过检查。

1. **身份与组织**：新增科目组长、校长、家长、个人用户四种身份；科目组；校长分管范围；对应的演示账号和演示数据。
2. **作业闭环**：合并作业与作品；状态流转；组长复核；改画与版本对比。
3. **校长查阅与驾驶舱**：批次查阅、批示；今日、教师、学生三个页签。
4. **教务闭环**：督办、学生档案、校长轮看、时限提醒与上报。
5. **导航**：两大板块和各角色首页。
6. **家长端**。
7. **个人模式**：免绑定、分层会员、购买流程。

## 10. 风险

- **一次做完的改动面**。会同时动到登录、导航、智慧校园、作业、作品、会员几处，中途任何一步出问题都会影响演示。所以第 8 节要求每一步单独验证、单独提交。
- **全部是演示数据**。闭环、驾驶舱、督办、家长端目前都没有真实后端接口，App 里先用本地演示数据实现，同时要把需要的接口补进后端缺口清单。
- **组长逐份复核的工作量**。假设一个组 5 位老师、每人每天点评 30 份，组长每天要看 150 份。需要批量通过这类轻操作，否则复核会长期积压。学生先看到老师点评（D6），所以积压不会拖慢学生拿到反馈。
- **后端归属**。作业现在在平台接口，作品在阅卷接口。合并后由哪个服务承载，需要后端决定。
- **iOS 上的个人购买**。在 iOS App 内出售会员通常要走苹果的应用内购买，属于原生改动，这台机器上无法编译验证。购买流程在这里只能做到演示数据层面，真实支付要在 Mac 上接入，并和负责上架的人确认做法。
- **行为数据的接受度**。指标口径对老师公开（D5），并且只统计闭环内的工作记录。
- **项目规则要同步改**。现有规则文件写定了左侧导航的项目，并要求继承页面保持原样，进入改代码阶段时要先更新这两条。
