# 美术之路 · 后端缺口清单

演示版的全部数据来自本地演示后端（`lib/core/demo/`）。关闭演示模式（`--dart-define=DEMO_MODE=false`）后，App 直接请求下面两套真实接口。本清单列出两套接口里**已经可用**、**需要后端补齐**和**需要产品决策**的部分，供排期使用。

依据：阅卷系统接口文档、`查分项目/docs/backend/2026-11-07/后端交接清单.md`、`查分项目/uni-app/api/*`（已对接正式服的学情小程序）。

## 一、两套接口

| 客户端 | 地址 | 鉴权 | 用到的模块 |
| --- | --- | --- | --- |
| 平台接口 `apiClientProvider` | `https://api-v2.yyzl0931.com/` | 请求头 `app-token` + `schoolId` | 账号、首页资讯、校园课件、云盘、视频、笔记、收藏、题库、AI、校圈、智慧校园、个人中心 |
| 阅卷接口 `markingApiClientProvider` | `https://exam-api.yyzl0931.com/` | 学生 `app-token`，老师 `school-token` | 学情中心、班级学情、作品档案、作品点评、范画库 |

两套接口统一返回 `{code, msg, data}`，`code == 0` 为成功。

- `growth` 与 `curve` 的数据点需要补 `participantCount`（交接清单 H-09），前端已读取该字段，人数不一致时会提示「前 X%」口径。

### 需要产品确认

- 学生端评委打分明细：真实接口对学生返回 403。App 的评委明细只在老师端（`ui/staff/`）展示，学生端只显示最终得分、档位与评语，与现状一致。是否对学生开放，需要产品决定。
- 机构统一满分、评分档位、公共标签库（交接清单 H-10）：上线后前端无需改动，作品级 `maxScore` 会自动锁定满分输入框。

## 三、平台接口

App 的通用模块沿用原平台（音乐之路，api-v2）的接口协议，路径保持不变：账号与内容在 `/app/user/*`、`/app/common/*`、`/app/msg/*`、`/app/courseware/*`，智慧校园在 `/app/school/v2/{student,teacher,manager,dormitory,chat,posts,user}/*`。演示数据按这些协议造数，内容替换成美术。

### 需要后端补齐（2.0 新增功能）

| 优先级 | 功能 | App 调用的接口 | 现状与建议 |
| --- | --- | --- | --- |
| P1 | 美术书刊 | `GET /app/ebooks/categories`、`GET /app/ebooks?category=&keyword=&sort=recommend\|latest\|popular&featured=&current=&size=`、`GET /app/ebooks/shelf`、`GET /app/ebooks/{id}`、`GET /app/ebooks/{id}/pages`、`GET/POST /app/ebooks/{id}/progress`、`POST /app/ebooks/{id}/favorite`、`POST /app/ebooks/{id}/bookmarks` | 平台没有书刊接口。列表项字段：`id`、`title`、`subtitle`、`editor`、`publisher`、`category`、`categoryLabel`、`subjects[]`、`stage`、`tags[]`、`pageCount`、`coverUrl`、`intro`、`featuredIntro`、`publishDate`、`readers`、`favorite`、`progress{page, updatedAt}`；详情另加 `description`、`toc[{title, page}]`、`related[]`；页面接口返回 `pages[{page, imageUrl, width, height}]`，建议签名 URL 并限时，避免整本下载；书架返回 `records`（带 `lastActiveAt`）、`readingCount`、`favoriteCount`。收藏同时写入通用收藏，`favoriteList` / `favoriteSave` 的 type 12 为书刊。演示版书刊均为自制示例（`sample: true`），正式上线需要取得授权的书刊与期刊。 |

| P1 | 校圈举报与治理 | `POST /app/school/v2/posts/postsReport`、`POST /app/school/v2/manager/postsReportList`、`POST /app/school/v2/manager/postsReportHandle`、`POST /app/school/v2/manager/postsDelete` | 平台没有举报与治理接口。同一条动态的多次举报合并为一条记录：`id`、`postsId`、`status`（0 待处理 / 1 已处理）、`result`（0 未处理 / 1 保留 / 2 删除）、`reportCount`、`reasons[{reason, count}]`、`reports[{reason, remark, createTime}]`（不含举报人身份）、`lastReportTime`、`handleReason`、`handleRemark`、`handlerName`、`handleTime`、`postDeleted`、`post`（删除后保留快照）。删除必须带原因；作者自行删除时待处理举报自动结案；`indexSum.postStatus0Count` 改为待处理举报数（按动态计）。参数、排序与报错文案见 `docs/走查/修复记录-F.md`。 |
| P2 | 首页今日课程 | `GET /app/user/nextSchoolCourse` | 首页与智慧校园课表必须同源：返回当天课程（节次 08:30–11:30 / 14:00–17:00 / 19:00–21:00），当天没课时返回最近一个有课的日子并带日期。 |
| P2 | 宿管按楼栋查寝统计 | 宿管端「查寝动态」目前复用班主任的班级查寝接口 | 宿管需要按管辖楼栋统计（走查 T-134）：已归寝、未归寝、请假、晚归与待审补卡，批次与下方列表一致。建议新增宿管专用接口。 |

需要决策：
1. **美术版用哪个平台后端**：独立部署一套美术版平台后端，还是复用 api-v2 并按学校隔离内容？复用时首页资讯、视频、课件、题库等内容要按「美术」打标签筛选。
2. **账号打通**：平台账号（手机号 + 密码，`app-token`）与阅卷系统的学生 / 老师账号是两套。需要确定绑定方式，例如：
   - 平台登录后用手机号换取阅卷 `app-token` / `school-token`；
   - 或阅卷系统作为统一身份源，平台接受阅卷 token。
   演示版用 `demo.<role>.<手机号>` 形式的令牌同时代表两边身份，接入真实接口前必须替换。
3. **角色映射**：智慧校园的学生、任课老师、班主任、宿管、管理员五种角色来自平台；作品点评、班级学情的老师身份来自阅卷系统。两边的老师需要一一对应。

Web 上新上传文件为当前文档的 Blob，刷新后不可恢复；生产需要持久上传和授权下载。二维码与交付文件保存已按文件能力调用，iPad 的系统文件面板、分享及原生权限仍需真机验收。

## 六、今日看板（今日学习 / 今日工作）

左侧导航「今日学习 / 今日工作」只渲染一份数据，页面自己不拼装、不计算；所有写操作都返回更新后的整份看板，页面直接替换。演示实现在 `lib/core/demo/fixtures/today/`，可以当作参考实现逐字段对照。

### 接口

均为平台接口（api-v2），请求体 JSON，身份取自登录令牌。

| 接口 | 入参 | 规则 |
| --- | --- | --- |
| `POST /app/today/board` | 无 | 按登录身份返回当天的看板。 |
| `POST /app/today/step/complete` | `id` | 打勾。只有 `manual` 为 true 的事可以；`kind` 为 `practice` 时把这件事的 `minutes` 记进当天练习时长。 |
| `POST /app/today/step/reopen` | `id` | 取消打勾，练习时长扣回。 |
| `POST /app/today/step/skip` | `id` | 今天不做。`required` 为 true 的事拒绝。跳过的事不计入进度。 |
| `POST /app/today/step/restore` | `id` | 把跳过的事放回清单。 |
| `POST /app/today/step/snooze` | `id`、`on` | 推迟到晚上再做 / 取消推迟。课程（`lesson`）拒绝。 |
| `POST /app/today/step/save` | `title`（1–30 字）、`slot`（morning / afternoon / evening / anytime）、`detail`、`time`（HH:mm，可空） | 添加自己的安排，每人每天不超过 10 件。 |
| `POST /app/today/step/delete` | `id` | 只能删除自己添加的安排。 |
| `POST /app/today/practice/log` | `minutes`（1–240） | 学生记录练习时长。 |
| `POST /app/today/people/follow` | `id`、`followed` | 标记一名学生或一件事已跟进 / 取消。 |
| `POST /app/today/tip/dismiss` | 无 | 不再显示用法提示。 |

业务错误按平台惯例返回非 0 `code` 和可以直接展示给用户的 `msg`。

### 看板结构

| 字段 | 说明 |
| --- | --- |
| `date` | `yyyy-MM-dd`，学校所在时区的当天。 |
| `role` | student / teacher / headTeacher / dormManager / admin / principal。 |
| `title` | 页面标题，如「今日学习」。 |
| `summary` | `total`、`done`、`remaining`、`overdue`（都不含已跳过的事），`streakDays` 与 `streakLabel`（如「连续完成」）。左侧导航角标取 `remaining`。 |
| `focusStepId`、`focusReason` | 「下一步」指向的那件事，以及一句为什么是它。全部完成时为空。 |
| `tipSeen` | 是否已关闭用法提示。 |
| `highlights[]` | 头图下面的数字卡，最多四张：`id`、`label`、`value`、`unit`、`caption`、`icon`、`tone`（purple / pink / teal / amber / blue）、`ratio`（0–1，可空，画进度环）、`trend`（这个数近几天的值，最后一个是今天，可空，画一排小柱子）、`action`。 |
| `groups[]` | 时间线分组：`id`（urgent / morning / afternoon / evening / anytime）、`title`、`caption`、`steps[]`。超时的事归到 urgent，推迟过的归到 evening。 |
| `charts[]` | 右侧图表，见下。 |
| `people` | 需要跟进的人：`title`、`empty`、`followLabel`、`rows[]`（`id`、`name`、`detail`、`value`、`followed`、`action`）。没有时为 null。 |
| `shortcuts[]` | 快捷入口：`label`、`icon`、`action`。 |

一件事（`steps[]`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 当天内稳定，写接口用它定位。 |
| `kind` | lesson / homework / revise / practice / reading / dorm / review / lead / approval / supervise / follow / message / patrol / punch / note / custom，决定图标和类型名。 |
| `title`、`detail` | 标题与一句说明。 |
| `time`、`endTime` | HH:mm，可空。有 `endTime` 的必做事过点未完成即为超时。 |
| `status` | todo / doing / done / overdue / skipped。 |
| `required` | 必做还是建议。 |
| `manual` | true：本人打勾；false：状态跟随业务数据（交了作品、点评完、审批完后自动完成）。 |
| `tag`、`tagTone` | 行内标签，如「今天截止」；tone 为 danger / warning / brand / good / neutral。 |
| `subject` | sketch / color / quick，可空。 |
| `source` | 这件事从哪来，如「李老师布置」。 |
| `minutes` | 建议时长，练习类用。 |
| `progress` | `done`、`total`、`unit`，如已点评 3 / 8 份。可空。 |
| `guide[]` | 「怎么做」的分步说明。 |
| `action` | 直达按钮，见下。可空。 |
| `custom`、`snoozed` | 是否本人添加、是否已推迟。 |

数量类的事（待点评、待审批等）以当天第一次看到的数量为总量，之后清掉的部分算进度；清零后保留为已完成，不从清单里消失。

`action.type` 与携带的字段：

| type | 字段 | 页面行为 |
| --- | --- | --- |
| `route` | `route`、`arguments` | 打开应用内页面。 |
| `campus` | `entry` | 打开智慧校园的某个视图，取值见 `CampusEntry`。 |
| `report` | `report`、`parameter`、`campus` | 打开教学报表，取值见 `TeachingReport`。 |
| `upload` | `taskId`、`parentId`、`title`、`subject` | 打开交作品 / 交修改稿对话框。 |
| `schedule` | — | 打开课表。 |
| `tool` | `tool` | 打开工具箱里的一个工具。 |
| `gallery` | `subject`、`keyword` | 打开素材中心。 |
| `practiceLog` | — | 打开记录练习时长。 |

每个 action 都带 `label`。页面遇到不认识的 type 不响应，可以先于客户端新增。

图表（`charts[]`）公共字段：`id`、`type`、`title`、`subtitle`、`caption`、`empty`（没有数据时的说明）、`action`、`headline`（`value`、`unit`、`label`、`delta`、`deltaGood`，可空）。

| type | 数据 | 用途 |
| --- | --- | --- |
| `meters` | `rows[]`：`label`、`value`、`max`、`text`、`caption`、`tone`、`tag`、`tagTone` | 几项进度或比例并排比较。 |
| `columns` | `unit`、`items[]`：`label`、`value`（可空）、`total`（可空）、`emphasis`、`note` | 按天或按类别的数量。 |
| `line` | `unit`、`target`、`targetLabel`、`points[]`：`label`、`value`（可空）、`note` | 一个数量随时间的变化，可带目标线。 |
| `parts` | `unit`、`parts[]`：`label`、`value`、`tone` | 一个整体分成几部分。 |
| `rooms` | `rooms[]`：`building`、`name`、`total`、`checked`、`state`（done：已查完；pending：有人没打卡；issue：有晚归或缺勤） | 宿舍查寝状态。 |
| `compare` | `columns[]`、`rows[]`：`label`、`cells[]`（`value`、`max`、`text`） | 校区之间几项指标对比。 |

`tone` 取 brand / good / caution / bad / neutral；绿、琥珀、红只表示状态。第一张图固定是 `week`（近 7 天完成情况），由服务端按每天的完成数与总数给出。

### 正式服务需要落实

| 项目 | 要求 |
| --- | --- |
| 数据口径 | 课表、作品任务与点评、审批、查寝、考勤等数量必须与各自模块的接口同源，不能另算一套。 |
| 状态持久化 | 打勾、跳过、推迟、自己的安排、练习时长、跟进标记按用户和日期保存；日期变更后生成新的一天，用法提示的关闭状态长期保留。 |
| 历史序列 | 近 7 天完成情况、练习时长、点评及时率、出勤率等需要按天留存；演示里是按账号和日期生成的稳定数。 |
| 权限范围 | 任课老师看所带班级，班主任看本班，教学组长另加所带科目的复核，管理员与校长看全校（校长含三个校区），宿管看管辖楼栋。 |
| 并发与幂等 | 同一件事重复打勾、重复跳过应得到相同结果；写接口返回的看板必须已包含本次改动。 |
| 时间 | 「现在」标记、超时判断和分组都以学校所在时区为准。 |

## 七、课程只有一种（去掉大课 / 小课）

美术画室没有大课、小课之分：每节课都是按班上课，由任课老师一键签课。应用里已经去掉课型、班型和只为另一种课存在的流程，后端对接时按下面的口径。

### 不再调用的接口

| 端 | 接口 | 原用途 |
| --- | --- | --- |
| 任课老师 | `teacher/schoolSmallCourseApplySave`、`schoolSmallCourseApplyList`、`schoolSmallCourseApplyDetail` | 申请排课与申请记录 |
| 任课老师 | `teacher/courseTeacherSignIn`、`courseTeacherSignOut` | 老师上课签到、下课签退 |
| 管理员 | `manager/schoolSmallCourseApplyList`、`schoolSmallCourseApplyDetail`、`schoolSmallCourseApplyAudit` | 排课申请审核 |
| 管理员 | `manager/courseSignSum1`、`courseCommentList`、`courseSignConfirm` | 另一种课的签课统计、学生评价、教务确认 |
| 学生 | `student/courseStudentSignIn`、`courseStudentSignOut`、`courseStudentComment` | 学生自己签到、签退、评价 |

### 字段变化

| 接口 | 变化 |
| --- | --- |
| 各端 `courseList`、`courseSignManager`、签课详情与历史 | 不再读 `type`；`signStatus` 只有 0（老师还没签课）和 2（已签课）；不再读老师下课时间、学生签退时间、评分和评价。 |
| `classList`、`classSave`、`classUpdate`、`classSum` | 班级没有 `type`；`classSum` 返回 `classCount`，不再分 `bigClassCount` / `smallClassCount`；请求里不再带 `type`。 |
| `manager/courseSignManager`、`courseSignSum0` | 请求不再带 `type`；统计只用 `courseCount`、`signedCourseCount`、`studentSignCount`、`studentShouldSignCount`、`makeupPendingCount`、`completedCount`。 |
| `manager/indexSum` | 去掉 `smallCourseSignStatus5Count`，新增 `courseSignMakeupStatus0Count`（课堂补签待审核条数），管理员首页「补签待审」、签课管理角标和今日工作都读它。 |
| `student/courseList` | 课程结束（老师已签课）后，每行附带本人的考勤结果：`signRecordId`、`studentSignStatus`（0 正常 / 1 缺勤 / 2 迟到 / 3 请假）、`studentSignInTime`、`signRemark`。学生端「课堂考勤」据此显示到课情况，不再单独拉详情。 |
| `student/courseSignMakeupSave` | 请求体只有 `courseId`、`reason`、`attachment`，不再区分上课签 / 下课签。 |
| `school/principal/teachers` 等老师履职 | 去掉 `studentRating`（来自另一种课的学生评价）。 |

### 正式服务需要落实

- 课表、签课、考勤和班级的表里如果还留着课型、班型字段，统一按一种处理，历史数据迁移时不要丢课次。
- 学生端的到课情况应当直接取任课老师签课的结果。演示里学生端和老师端的考勤各自生成，同一节课两边可能不一致，上线前要改成同源。
