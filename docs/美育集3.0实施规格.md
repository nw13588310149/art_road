## 2. 作品点评链：数据

### 2.1 存储

- 种子不落盘：每次启动按 `DemoClock.now()` 重新生成最近 8 周的数据（固定种子，按「日期 + 学生 + 作业」确定，同一天重复生成结果一致）。这样隔几天再打开演示，仍有「今天」「近 7 天」的数据。
- 写入只存差异：用户新交的作品、被改动过的作品（点评、复核、校长点评、推优）整条存进 `DemoStore`，读取时覆盖同 id 的种子。键名带 `v3`，旧的 `v2` 键不再读取。
- 统一从一个入口读写（例如 `DemoArtworkStore`），平台消息、首页、智慧校园都走它，不再各自 `DemoStore.list(worksKey, …)`。

### 2.2 一份作品

```
id, rootId, version(1 起), parentId(上一版 id，没有为空)
personIndex, title, subject, drawingDate, createTime, description, images[{id, ref}]
taskId(自主练习为空), teacherId(责任老师)
review: null | {
  teacherId, score|null, maxScore, content, reviewedTime,
  dimensions: {key: 1..5},            // 四项分项，见 2.3
  tags: [{id, name, explanation, color, dimension}],
  voiceRef, voiceSeconds,              // 语音评语，可空
  requestLeadReview: bool,
  tagResolutions: [{tag, resolved}]    // 仅改画版本：上一版问题标签逐个标「已改善 / 仍需加强」
}
supplements: [{teacherId, content, time}]   // 其他老师的补充点评，不计分
leadReview: null | {
  reasons: [REQUESTED | SCORE_ANOMALY | BRIEF | SPOT_CHECK], enteredTime, leaderId,
  action: null | KEEP | ADJUST | SUPPLEMENT, score, reason, content,
  qualityStars(1..5), qualityNote, time
}
principalComments: [{id, userId, name, content, time}]
featured: bool, featuredTime, featuredBy
```

读取时计算，不落盘：

- `status`：`PENDING`（待点评）/ `REVIEWED`（已点评）。
- `leadStatus`：`NONE` / `IN_REVIEW`（复核中）/ `DONE`（已复核）。
- `finalScore`：组长调分后取组长的分数，否则取责任老师的分数。
- `overdue`：待点评且提交超过点评时限；`leadOverdue`：复核中且进入复核池超过复核时限。
- `timeline[]`：按时间排的事件，`role` 为 `STUDENT / TEACHER / LEADER / PRINCIPAL`，`type` 为 `SUBMIT / REVIEW / SUPPLEMENT / LEAD_KEEP / LEAD_ADJUST / LEAD_SUPPLEMENT / PRINCIPAL_COMMENT / FEATURE`，带 `name、time、content、score、fromScore、toScore`。

谁能看到什么：

| 内容 | 学生 | 责任老师 | 组长 | 校长、管理员 | 班主任 |
| --- | --- | --- | --- | --- | --- |
| 老师点评（分数、分项、标签、评语、批注、语音） | 点评后立即可见 | 是 | 本组 | 全部 | 本班，只读 |
| 进入复核的原因 | 否，只显示「复核中」 | 是 | 是 | 是 | 否 |
| 复核结果（维持 / 调分及理由 / 补充评语） | 是 | 是 | 是 | 是 | 是 |
| 点评质量星级与意见 | 否 | 本人的 | 是 | 是 | 否 |
| 校长点评、优秀作品标记 | 是 | 是 | 是 | 是 | 是 |

管理员只读；校长可以点评和推优，不改分。

### 2.3 分项

每科四项，每项 1–5 级：待加强 / 一般 / 合格 / 良好 / 优秀。

| 科目 | key 与名称 |
| --- | --- |
| 素描 | `composition` 构图、`form` 造型、`value` 明暗、`rendering` 刻画 |
| 色彩 | `composition` 构图、`form` 造型、`color` 色彩关系、`rendering` 刻画 |
| 速写 | `composition` 构图、`gesture` 比例动态、`line` 线条、`rendering` 刻画 |

点评标签增加可选的 `dimension`。分项水平 = 最近 10 份已点评作品的分项等级均值，按科目算。

### 2.4 规则

- 时限：点评 24 小时（从提交算），复核 48 小时（从进入复核池算），抽查比例 20%，都放在「点评设置」里，教务可改（抽查 10%–50%）。
- 进入复核池（老师保存点评时判断，满足任一条，记下全部命中的原因）：
  1. 老师勾了「请组长复核」；
  2. 分数异常：与该生最近 5 次同科最终分的均值相差不少于满分的 15%（不足 2 次不判）；
  3. 点评过简：评语少于 20 字且没有批注；
  4. 抽查：按作品 id 的固定散列值与抽查比例比较。
- 复核：维持；调分（理由至少 10 字，最终分改为组长的分数，原分保留在时间线里）；补充评语。每次复核必须给 1–5 星。
- 改画重交：新版本 `version + 1`、`parentId` 指向上一版、`rootId` 不变，责任老师不变。学生列表每条链只显示最新一版并带「共 N 版」。
- 满分沿用现有规则（默认 100，可以不打分只写评语）。
- 消息（`targetType = 2`，`targetId` 为作品 id，写入对方的 `notices:v2:<userId>`，对方还没读过消息时也要能看到）：
  - 学生提交 → 责任老师；
  - 老师点评 → 学生；
  - 组长调分或补充评语 → 学生和责任老师；组长维持 → 只通知责任老师；
  - 校长点评、推优 → 学生、责任老师、班主任。

### 2.5 作业（任务）

作业和作品同库：`{id, teacherId, classIds[], subject, title, requirement, dueTime, createTime, referenceWorkId(范画，可空)}`。作品用 `taskId` 关联。智慧校园「作业」两个页面改读这份数据放在第三期，第一期只生成数据并提供 2.6 里的接口。

### 2.6 接口（阅卷接口一侧）

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 学生作品列表 | `GET /app/artworks?status=&revised=&current=&size=` | 每条加 `status、leadStatus、version、versionCount、rootId、taskId、taskTitle、teacherName、hasPrincipalComment、featured` |
| 学生作品详情 | `GET /app/artworks/{id}` | 加 `review、supplements、timeline[]、versions[]、dimensions[]（本科目四项的 key 与名称）` |
| 提交作品 | `POST /app/artworks` | 加 `taskId、parentId` |
| 学生统计、小结 | `GET /app/artworks/statistics`、`/insights` | 小结加分项水平、问题解决率、连续练习天数、近 7 天提交数 |
| 优秀作品墙 | `GET /app/artworks/excellent?subject=&current=&size=` | 全校可见，带学生姓名和班级 |
| 学生的作业 | `GET /app/tasks?status=` | 待提交 / 已提交 / 已点评 |
| 老师队列 | `GET /school/teacher/artworks?status=&keyword=&subject=&campus=&teacherId=&current=&size=` | 老师只看自己负责的；校长、管理员看全部并可筛选；班主任看本班 |
| 老师详情 | `GET /school/teacher/artworks/{id}` | 责任老师、本组组长、校长、管理员、班主任可读 |
| 老师统计 | `GET /school/teacher/artworks/statistics` | 加 `overdue` |
| 保存点评 | `POST /school/teacher/artworks/review?next=` | 加 `dimensions、requestLeadReview、tagResolutions、voiceUrl、voiceSeconds` |
| 补充点评 | `POST /school/teacher/artworks/{id}/supplement` | 非责任老师，不计分 |
| 批注 | `GET/POST /school/teacher/artworks/{id}/annotations` | 组长、校长可读责任老师的批注 |
| 布置作业 | `GET/POST /school/teacher/tasks` | |
| 复核池 | `GET /school/leader/reviews?status=&reason=&teacherId=&current=&size=`、`GET /school/leader/reviews/statistics` | 只返回本组（按科目）的作品 |
| 提交复核 | `POST /school/leader/reviews/{artworkId}` | `action、score、reason、content、qualityStars、qualityNote` |
| 校长点评、推优 | `POST /school/principal/artworks/{id}/comment`、`POST /school/principal/artworks/{id}/feature`（`featured: true/false`） | |
| 点评设置 | `GET/POST /school/review-settings` | 抽查比例、两个时限、组长名单（只读） |

错误用 `DemoApiException` 抛中文提示（没有权限、理由太短、星级没选等）。

### 2.7 种子数据要求

- 作业：每个班每周每科 1 次，由该班该科老师在有课的那天布置，次日晚截止。8 周共约 70 次。
- 提交：在校学生（38 号休学不交）约 88% 按时交，少数迟交或不交；另有少量自主练习。提交时间落在课后时段（11:30–13:00、17:00–18:30、20:30–21:30），不晚于 `DemoClock.now()`。周日不上课，不产生作业和提交。
- 分数与学情一致：以该生最近月考的同科成绩为中心上下浮动，林小雨仍是素描最高、色彩有待加强。
- 老师之间要有差别，校长才看得出问题。示例口径（可微调，但要拉开差距）：李静及时、评语充分；王海波偏慢，有 5–8 份超时未点评，评语偏短；赵雪居中；周强偏严（打分低于组内均值）。
- 复核：按 2.4 的规则真实触发。张明远名下留 6–10 份待复核，其中 1–2 份超时；已复核里有维持、调分、补充三种，星级有高有低。
- 校长：约 12 份优秀作品（三科都有），约 15 条校长点评。
- 改画：约 8% 带问题标签的作品有第 2 版，其中七成问题标「已改善」。
- 林小雨（学生演示账号）手工编排，保持她的故事完整：
  - 待点评 2 份（在李静的队列里，其中 1 份是今天交的）；
  - 一份走完全链路的素描：李静点评 → 张明远调分 → 校长点评并推优；
  - 一条改画链（第 1 版问题 → 第 2 版改善）；
  - 一份「复核中」；其余为已点评。《石膏头像结构练习》保留，李静的评语开头仍是「结构交代清楚，暗部再整体一些」。
- 李静名下：待点评 8–12 份，其中 2 份超时。赵雪名下：待点评 3–5 份。

## 7. 执行手册（各子任务通用）

每个子任务在自己的 git 工作树和分支里做，互不干扰，做完由总控合并回 `main`。

1. **只在分配给你的工作树目录里读写**。主目录 `d:\桌面\阅卷系统\art-road` 和参照工程 `D:\桌面\music\musicDemo` 只读。
2. 进工作树后先跑一次 `flutter pub get --offline`。
3. 改动过程中随时跑 `dart analyze lib test` 和相关的 `flutter test --no-pub test/<文件>`；收尾时两条命令全量跑一遍，必须 0 问题、全部通过。原有测试断言与新版式冲突时，改测试并在汇报里说明改了什么、为什么。
4. 涉及界面的任务要看图验收：
   - 构建：在工作树里运行 `tool/build_web.ps1`（约 3–5 分钟，尽量攒够改动再构建，一个任务不超过 4 次）。
   - 起服务：`python -m http.server <分配给你的端口> --directory build/web`（后台运行，任务结束前关掉）。
   - 截图：`node tool/qa/screens.mjs --base=http://127.0.0.1:<端口> --out=build/qa/<任务名>-1180 --roles=<身份> --only=<步骤前缀>`，再加 `--width=1024 --height=768 --out=build/qa/<任务名>-1024` 跑一遍。步骤在 `tool/qa/pages.mjs`，新页面、新入口要加步骤，并带一个能证明页面真的打开了的 `check`。
